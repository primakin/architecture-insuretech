# Cписок проблем и рисков, связанных с планируемым ростом нагрузки
	
1. Информацию о доступных продуктах сервисы получают синхронно. Как следствие, недоступность внешних систем страховых компаний приводит к ошибкам/задержкам на стороне `ins-product-aggregator` и далее по цепочке в `core-app` и `ins-comp-settlement`. С ростом нагрузки проблемы будут только усугубляться.
2. `core-app` и `ins-comp-settlement` хранят локальные реплики данных о продуктах, но обновляют их с разной периодичностью (раз в 15 минут и раз в сутки соответственно) - потенциально это может приводить к неконсистентности реплик.
3. `ins-comp-settlement` запрашивает список оформленных страховок у `core-app` синхронно - с ростом нагрузки время обработки запросов будет только возрастать.

# Решение
1. Используем event streaming для передачи информации по продуктам и тарифам из `ins-product-aggregator` в `core-app` и `ins-comp-settlement` через Kafka. Информация о продуктах и тарифах хранится централизованно в `ins-product-aggregator-db`. Для решения потенциальной проблемы несогласованности данных в БД и Kafka используем transactional outbox.
2. Используем event streaming для передачи информации по оформленным страховкам из `core-app` в `ins-comp-settlement` через Kafka (с transactional outbox).
